# 얼굴 검사 로그·기능 설정·움직임 대응 개선 (2026-10-03)

사용자 요청에 따라 Phase 7 화면에 **로그**와 **기능 설정** 메뉴를 추가하고, 머리 영역 우선 검출과 여러 프레임 비교를 native 서비스에 적용했다. 인물 관리는 마지막 메뉴에 유지한다. 기존 카메라·인물·등록 사진과 이벤트 인증·중복 방지·재연결 복구를 유지한다. 비상업 시험 목적이며 모델/가중치/외부 의존성은 변경하지 않았다.

## 화면과 API

| 기능 | 경로 / 동작 |
| --- | --- |
| 로그 화면 | `#/logs`, 카메라·결과·주요 사유·기간 필터, 집계, 상세 지표, 50건씩 cursor 조회 |
| 로그 API | `GET /api/recognition-logs`, 로그인 및 카메라 조회 grant 검사 |
| 기능 설정 화면 | `#/settings`, 저장값·적용값·반영 상태 및 검사 빈도 입력 |
| 설정 조회 | `GET /api/function-settings`, 로그인 |
| 설정 저장 | `PUT /api/function-settings`, 관리자·CSRF·revision 충돌 검사 |

로그는 실제 검사한 프레임만 기록한다. 검출 실패, 여러 얼굴, 품질 제외, 사진 수집, 등록 얼굴 없음, 평균 점수 미달, 프레임 간 비교 불일치, 후보 및 검색 서비스 장애를 구분한다. 모든 품질 제외 사유를 보관하고 집계/사유 필터는 첫 번째 사유를 사용한다. 품질 제외 프레임에는 이전 사진의 비교 점수를 붙이지 않는다. 사진·embedding·인물 이름·RTSP 접속 정보는 로그에 포함하지 않는다.

카메라·세션·추적·프레임 조합은 UNIQUE이며 저장 재시도 시 중복을 건너뛴다. 별도 writer의 큐는 기본 256건이고 최대 64건씩 저장한다. DB 실패는 세 번 재시도하며 큐 포화/저장 실패는 worker의 `recognition_logs` 통계에 표시한다. 로그 보관은 기본 7일/100,000건이다. 카메라 삭제 시 해당 진단 기록도 삭제한다. 일반 계정은 사용 중인 카메라의 조회 grant가 필요하고 권한 변경은 다음 조회에 반영된다.

## 실행 중 설정 반영

| 설정 | 범위 | 최초 기본값 |
| --- | --- | --- |
| 사람 검출 기준 점수 | 0~1 | 0.10 |
| 사람 검출 빈도 | 1~15 FPS | 5 FPS |
| 인물별 얼굴 검사 간격 | 0.2~10초 | 0.5초 |
| 프레임당 최대 얼굴 검사 인원 | 1~16명 | 4명 |
| 얼굴 비교점수 기준 | -1~1 | 0.75 |

DB의 `function_settings` singleton에 revision과 값을 저장한다. 최초에는 `.env`를 사용하고 화면에서 저장한 값이 이후 우선한다. worker는 시작 시 저장값을 읽고 2초마다 변경을 확인한다. API는 내부 인증 명령으로 즉시 적용을 요청한다. scheduler가 프레임 사이에서 설정과 ByteTrack의 FPS/분실 프레임 상한을 변경하며 기존 세션·추적 ID·얼굴·이벤트 중복 방지 키를 유지한다.

저장 후 반영 확인이 지연되면 API는 `202`와 미반영 상태를 반환한다. 화면은 실제 적용값을 별도로 표시하고 반영될 때까지 확인한다. 다른 화면이 먼저 저장했으면 `409`로 기존 편집 내용의 덮어쓰기를 막는다. NaN/무한대·범위 밖 값·정수가 아닌 검사 인원·추가 필드는 거절한다.

### 사람 검출 기준 점수 추가 (2026-10-04)

**기능 설정 → 사람 검출 기준 점수**에서 YOLO 신뢰도 하한을 입력한다. 저장 시 `detection_confidence`를 기존 네 항목 및 `revision`과 함께 전송한다. `function_settings.values` JSON을 사용하므로 migration은 추가하지 않는다. 기존 JSON에 항목이 없으면 `DETECTION_CONFIDENCE`(기본 0.1)를 사용하며 다른 저장값은 보존한다. 빈 값·NaN·무한대·0~1 밖의 값은 거절한다.

GPU scheduler가 프레임 사이에서 실제 `YoloPersonDetector.confidence`와 상태의 `detector.confidence_threshold`를 갱신한다. 다음 단일 또는 batch 검출의 YOLO `conf` 인자로 이 값을 전달한다. 시작 시 저장값을 읽은 뒤 모델의 초기값도 맞추므로 서비스 재시작 후 적용 상태와 실제 모델 값이 일치한다. 카메라를 재시작하거나 추적 객체를 새로 만들지 않는다. `result.detection_confidence`는 해당 프레임의 적용값이며 Live Search의 **상세 분석 지표 → 사람 검출 기준**에 표시한다.

검출 기준은 추적기의 low/high/new 기준(기본 0.10/0.50/0.60)과 독립적으로 조정한다. 높이면 낮은 점수의 후보가 추적기에 도달하지 않는다. `Settings`의 검증은 low < high ≤ new 관계를 유지하고 검출 기준 자체는 0~1을 허용한다. 얼굴 검출 테스트의 SCRFD 검출 기준은 별도 설정이다.

전체 backend **176건**, frontend 논리 **19건**, TypeScript·Angular production build(**617.76 kB**)·Ruff·diff 검사를 통과했다. 기존 설정 보완·유효값 저장·실제 YOLO 호출 인자·시작 시 값 반영·실행 중 검출 결과 변경·추적 객체/세션 유지와 기준 복원을 확인했다.

실제 CUDA/Chrome에서는 입력 검증·저장·적용값·새로고침 복구·모바일 화면을 확인했다. 임시 카메라의 공개 시험 영상에서 사람 검출 기준 **0.20 → 1.00 → 0.20** 변경 시 같은 영상 세션을 유지하면서 **검출 있음 → 0명 → 검출 복구**를 확인했고 Live Search의 적용값 표시 및 기존 이벤트 보존도 통과했다. 검사에 사용한 설정은 사용자 원래 값으로 복원하고 임시 카메라·인물만 정리했다. worker/backend에 반영했으며 모델·의존성 변경은 없다.

## 얼굴 검출과 비교

- 여유 영역을 포함한 사람 위쪽 절반을 320px 입력으로 먼저 검사한다. 미검출·작은/잘린 얼굴·특징점 오류에는 전체 사람 영역으로 검사하고 필요한 경우 640px로 재검사한다. 총 세 패스 안에서 처리하며 이웃 얼굴·여러 얼굴 연결 제한을 유지한다.
- SCRFD의 resize, anchor grid와 ONNX shape annotation을 320/640 입력에 맞췄다. 모델 시작 시 두 크기를 실제 추론하고 640 출력 개수를 검사한다. 기존 CUDA convolution 검증을 유지한다.
- 품질을 통과한 사진은 이전 best보다 점수가 낮아도 embedding을 만든다. 최근 최대 5장을 유지하고 사진별 인물 최대 reference 점수를 품질에 따라 평균한다. 평균이 기존 기준 0.75 이상이며 최소 2장도 각각 기준 이상일 때 후보로 표시한다.
- 사용 시간은 기본 3초이며 긴 검사 간격에서는 두 장을 확보하도록 간격×2.5까지 늘린다. 사진·후보 evidence는 만료 시 해제하고 세션 교체·추적 만료에서 버퍼를 비운다. 모든 기존 사진과 cosine 0.3 미만인 큰 특징 변화도 버퍼를 초기화한다. 이 기준은 시험 설정이다.
- 대표 썸네일은 최근 사진 중 최고 품질이다. 이벤트 사진·프레임·시각·품질은 해당 후보의 기준을 충족한 사진 중 최고 품질로 연결한다. 기존 event UNIQUE, cooldown, 권한·검토와 WebSocket/HTTP 복구를 유지한다.

## 2026-10-04 업로드 영상의 얼굴 직접 검출·등록 인물 비교

사용자가 업로드 영상에 한정해 요청한 얼굴 직접 검출과 등록 인물 비교·검색 이벤트를 구현했다. 기능 설정에 다음 값을 추가하고 기존 JSON에 저장한다. 새 DB migration은 없다. 이전 설정의 빠진 값은 기본값으로 보완하며 이전 클라이언트가 기존 항목만 저장해도 새 설정값을 덮어쓰지 않는다.

| 설정 | 범위 | 기본값 |
| --- | --- | --- |
| 사람 검출 사용 | 체크 / 해제, 업로드 MP4에 적용 | 체크 |
| 얼굴 검출 기준 | 0.10~0.99, 얼굴 직접 검출 모드 | 0.50 |
| 최소 얼굴 크기 | 8~512 px 정수, 원본 얼굴 영역의 짧은 변 | 8 px |

체크를 끈 MP4는 YOLO를 호출하지 않고 얼굴 검출 테스트와 같은 `detect_all`로 전체 화면과 겹치는 960px 분할 영역을 640px 입력으로 검사한다. 같은 `align_detected_face`를 사용해 정렬 오차 12 이하·16px 이상인 얼굴의 특징을 만든다. 검출 최소 크기가 8~15px인 얼굴은 표시할 수 있지만 특징 비교 조건은 별도다. 엄격한 실시간 자세·밝기·선명도 제외 조건을 이 업로드 경로에 추가하지 않는다. 대표 사진은 검출 신뢰도·선명도·면적 점수를 0~1로 정규화해 선택한다.

얼굴 박스의 공간 겹침으로 카메라·세션 내 임시 추적 번호를 유지한다. 같은 프레임의 얼굴은 서로 다른 번호를 갖고, 캐시는 기존 수량·분실 시간 상한을 따른다. 기존 최근 사진 캐시·품질 가중 평균·최소 두 장의 기준 이상 결과를 등록 인물 비교에 사용한다. 기존 gallery, 인증된 얼굴/이벤트 이미지, MatchEvent 중복 방지·WebSocket, 로그와 영상 클립 경로를 재사용한다. 몸 영역 Re-ID는 얼굴 직접 검출 모드에서 실행하지 않는다.

모드 변경은 업로드 영상의 추적 세션을 교체하고 이전 후보·특징·미리보기를 비운다. 얼굴 검출 기준이나 최소 크기 변경은 기존 얼굴 사진 캐시를 비우고 다음 프레임부터 새 조건으로 검사한다. 새 등록 인물 비교 경로는 실제 입력 유형이 MP4인 경우에만 선택하며 RTSP의 기존 처리 경로에는 적용하지 않는다. 업로드 영상도 Live Search의 최신 프레임 우선·검사 빈도/간격·검사 인원 상한을 유지한다. 얼굴 검출 테스트처럼 모든 프레임을 순차 처리하거나 완료 후 영상 전체 묶음을 재병합하는 기능은 이 화면에 추가하지 않았다. 두 화면은 입력 범위와 검출/정렬 구현을 공유하고 설정값은 별도로 저장한다.

전체 backend 181건(신규 5건), frontend 논리 19건, 타입/production build/Ruff, 기존 Chrome 3건과 신규 업로드 얼굴 모드 Chrome 1건을 통과했다. 새 시험은 실제 CUDA와 공개 시험 MP4에서 얼굴 2개·등록 인물 후보·인증된 112px 사진·검색 이벤트·반복 프레임의 중복 방지, 최소 512px/검출 기준 0.99에서 0개 및 조건 복구, 사람 검출 복귀 시 새 세션, 설정 복구·입력 범위·정수 검증·모바일 가로 넘침을 확인했다. 최초 새 브라우저 시험은 메뉴의 장식 문자와 정확한 이름 비교가 맞지 않아 분석 시작 전에 멈췄다. 시험 선택 조건과 종료 시 정리 시간을 수정해 통과했으며 남은 임시 인물·카메라도 정리했다.

backend·worker 서비스를 재시작하고 설정의 실제 반영을 확인했다. 기존 카메라 3개·인물 2명·얼굴 검출 테스트 결과 5개·사용자 설정·카메라 중지 상태를 보존했다. 검증용 설정은 원래 값으로 복원했으며 새 항목은 기본값인 체크/0.50/8px다. 검증 기록은 `data/reports/uploaded-faces-regression.json`, backend 결과는 `uploaded-faces-backend.xml`, 화면은 `data/screenshots/uploaded-faces-live.png`에 보관한다. 이 시험은 공개 정지 사진을 반복하는 영상의 기능 확인이며 움직이는 영상의 정확도 보정은 포함하지 않는다.

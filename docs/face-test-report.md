# 다크 테마와 얼굴 검출 테스트 (2026-10-04 KST)

전체 페이지를 다크 테마로 변경하고 왼쪽 메뉴 마지막에 **얼굴 검출 테스트**를 추가했다. 비상업 시험 목적을 유지하며 기존 모델과 의존성을 재사용한다. DB migration head는 `0007_event_clips`를 유지한다.

## 사용 방법

1. **얼굴 검출 테스트**에서 파일 입력 위의 **검출 기준**, **최소 얼굴 크기**, **비교점수 기준**을 입력하고 **분석할 영상 파일**을 선택한다. 검출 기준은 0.10~0.99, 최소 크기는 8~512 px 정수, 비교점수 기준은 -1~1이다. 최소 크기는 원본 영상의 얼굴 영역에서 가로·세로 중 짧은 변을 기준으로 하며 사진의 여백이나 640px 모델 입력 크기를 기준으로 하지 않는다.
2. 파일 입력 아래의 **영상 분석**을 누르면 업로드 후 비동기 분석을 시작한다. 프레임 처리 진행률과 검출 횟수를 표시한다.
3. 얼굴 특징의 cosine 유사도로 같은 영상 안의 얼굴을 묶고 인물별 대표 사진을 격자로 표시한다. 모든 프레임을 처리하면 **얼굴 묶음 병합 중** 상태에서 분리된 묶음을 다시 비교하고, 완료 시 병합 전후 묶음 수와 병합 개수를 표시한다. 합친 묶음의 검출 횟수와 첫/마지막 등장 시각을 통합하고 얼굴 크기·선명도·검출 신뢰도가 가장 좋은 대표 사진 한 장을 남긴다.
4. 새로고침하거나 다른 화면으로 이동했다 돌아와도 저장된 결과를 복구한다. 여러 영상을 분석한 경우 결과 영상 선택 목록에서 조회한다.
5. **목록 전체 삭제**는 현재 계정의 분석 작업을 중지하고 모든 시험 영상 목록·추출 사진을 실제로 삭제한다. 카메라 영상, 인물 등록 사진, 검색 이벤트에는 영향을 주지 않는다.

로그인한 계정은 자신의 영상과 결과만 사용할 수 있다. 관리자도 다른 계정의 시험 결과를 조회하지 않는다. 업로드·삭제는 기존 session cookie와 CSRF 검증을 사용하고 얼굴 이미지도 인증된 API로만 반환한다.

검출 기준의 기본값은 기존 `FACE_DETECTION_THRESHOLD`(기본 0.5), 최소 크기는 기존 시험 추출과 같은 8 px다. 이 두 값을 높이면 작은 얼굴이나 신뢰도가 낮은 후보를 제외한다. 비교점수 기준의 초기값은 현재 기능 설정의 값이며 영상마다 직접 지정할 수 있다. 이 값은 프레임 처리 중 같은 인물 묶기와 마지막 재병합에 함께 사용한다. 낮추면 더 많이 합칠 수 있지만 다른 인물을 합칠 가능성도 커진다. **영상 분석**을 누르면 해당 영상의 적용값을 저장한다. 결과에 적용값을 표시하고 새로고침 시 가장 최근 영상의 값을 입력란에 복구한다. 입력값 변경은 다음 분석부터 적용되며 Live Search나 인물 등록의 공유 설정을 바꾸지 않는다. 기존 결과는 그대로 유지한다. 이전 결과의 얼굴 특징과 원본은 보관하지 않으므로 새 재병합 기능을 적용하려면 영상을 다시 업로드해 분석한다.

## 분석 및 저장

- 기존 Live Search의 FPS 샘플링·YOLO 사람 ROI·프레임당 얼굴 수 설정을 사용하지 않는다. OpenCV로 처음부터 EOF까지 연속 디코딩하고 모든 프레임에서 SCRFD 얼굴 탐지를 수행한다. 고해상도 영상은 화면 전체 640px 검사에 960px 영역/192px 겹침 검사를 더하며 겹치는 검출을 제거한다.
- Live 모델의 기본 10개 얼굴 상한은 그대로 유지하고 시험 분석에서만 제거한다. 처리 상한을 초과하면 명시적인 실패와 중단 전 결과를 반환하며 완료로 처리하지 않는다. 예상 프레임 수보다 적게 디코딩된 영상도 실패로 표시한다.
- 얼굴마다 5-point alignment와 ArcFace 특징을 생성한다. 등록 사진의 엄격한 품질 검사를 통과하지 못한 얼굴도 이 페이지에서는 추출한다. 정렬이 불가능한 얼굴은 특징 비교 없이 가까운 연속 프레임의 위치로 임시 묶고 카드에 **얼굴 비교 불가**를 표시한다.
- 묶기 기준은 분석 시작 시 영상별 비교점수 입력을 저장해 사용하며 생략한 요청은 기능 설정의 현재 값을 사용한다. 프레임 처리 중 그룹별 최대 8개 특징으로 평균 특징을 갱신한다. 모든 프레임을 처리한 뒤 최종 평균 특징의 cosine 유사도로 묶음을 재비교하고 가장 비슷한 묶음부터 합친다. 이미 합친 묶음에 포함된 모든 원래 묶음 쌍이 기준 이상이어야 하므로 A-B, B-C만 비슷한 연결 때문에 A-C까지 합치지 않는다(complete linkage).
- 같은 프레임에 함께 등장한 묶음은 RAM의 제한된 비트 마스크로 기록하며 재병합에서도 합치지 않는다. 이 제외 조건은 병합을 거친 묶음에도 전파한다. 얼굴 특징을 만들지 못한 묶음은 재병합에서 유지한다. 그룹별 특징·평균 특징·동시 등장 마스크·재비교 행렬은 RAM에만 유지하며 JSON·DB·Qdrant에 저장하지 않는다. 특징이 같더라도 서로 다른 영상의 결과는 합치지 않는다.
- 병합 후 가장 선명한 대표 JPEG를 유지할 그룹 ID에 복사한 뒤 최종 결과를 저장하고 제거된 그룹의 중복 JPEG만 삭제한다. 최종 저장 전에는 원래 그룹 사진을 삭제하지 않는다. 병합 중 전체 삭제도 취소 신호와 worker 종료를 기다려 해당 계정의 파일을 정리하며, 병합 중 재시작된 작업은 다른 미완료 작업과 같이 실패로 복구한다.
- 기본 제한은 업로드 200 MB, 최대 3840×2160/60분/432,000프레임, 프레임당 검출 얼굴 100개, 영상당 인물 묶음 500개, 계정별 영상 10개/전체 100개, 시험 저장 공간 1,000 MB다. 전체 서비스를 통틀어 영상 시험 작업 하나만 실행하고 한 프레임씩 기존 공유 GPU 스케줄러에 제출한다. 카메라와 사진 비교 작업도 같은 스케줄러에서 계속 처리하므로 동시 실행 시 처리 속도에는 영향을 줄 수 있다.
- 영상 원본은 완료·실패·중지 후 삭제한다. `data/face-tests/`에 UUID별 JSON과 대표 JPEG만 보관하고 기본 24시간 후 정리한다. 디렉터리 0700, 파일 0600이며 API 응답은 `no-store`다. worker 재시작 시 완료된 결과는 복원하고 미완료 작업은 실패로 표시하며 원본을 정리한다.

모델이 검출할 수 있는 얼굴을 추출하는 시험 기능이다. 가림, 작은 얼굴, 흐림, 큰 자세 변화에서는 검출 누락이나 묶음 분리/오병합이 가능하다. 아래 공개 정지 사진 반복 영상 결과는 기능 동작 확인이며 움직이는 영상의 정확도 보정이나 동일인 확정 결과가 아니다.

## 설정과 API

`.env.example`의 `FACE_TEST_*` 값으로 결과 보관 기간·전용 저장 용량·계정별 영상 수·인물 수·프레임당 얼굴 수·길이 제한을 변경할 수 있다. 변경 후 worker와 backend를 재시작한다. 기존 `VIDEO_UPLOAD_MAX_MB`, `STORAGE_MIN_FREE_BYTES`도 사용한다.

| Method | 경로 | 용도 |
| --- | --- | --- |
| GET | `/api/face-tests` | 내 결과 목록·업로드 가능 여부·제한·검출 기본값(`defaults`) |
| POST | `/api/face-tests?filename=example.mp4&detection_threshold=0.8&min_face_size=32&match_threshold=0.75` | 원시 영상 body 업로드 및 영상별 검출·묶기 설정으로 분석 시작, 202 |
| GET | `/api/face-tests/{job_id}` | 내 작업의 진행 상태와 인물 묶음 |
| GET | `/api/face-tests/{job_id}/groups/{group_id}/image` | 내 대표 얼굴 JPEG |
| DELETE | `/api/face-tests` | 내 실행 작업 중지 및 전체 결과·파일 삭제 |

query를 생략하면 기존 기본값으로 분석한다. `defaults.match_threshold`는 현재 기능 설정의 비교점수 기준이다. 범위를 벗어나거나 유한하지 않은 검출 기준·비교점수 기준, 정수가 아닌 최소 크기는 업로드를 저장하기 전에 422로 거절한다. 새 작업 JSON에는 `detection_threshold`, `min_face_size`, 비교점수 기준인 `threshold`, `groups_before_merge`, `merged_group_count`를 저장하며 이전 작업 JSON도 계속 조회할 수 있다. 공유 모델의 검출·비교 기준은 변경하지 않고 해당 영상의 값을 사용한다.
